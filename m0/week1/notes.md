### 思考题：指针和引用的核心区别（给你对照参考，整理到 README）

1. **指针可以为空、可以不初始化；引用定义时必须立刻绑定一个有效变量，不能是空**

## 主题：new /delete 堆内存分配释放

### 基础语法（大白话）

- 栈变量（`int a=10`）：函数执行结束，内存自动回收
- `new`：手动向系统申请**堆内存**；堆内存不会自动回收，必须手动 `delete` 还给系统
- `new int`：申请一块存单个 int 的堆空间，返回这块空间的首地址（指针）
- `new int[N]`：申请连续 N 个 int 的堆数组，返回数组首地址
- `delete 指针`：释放 `new` 申请的单个变量内存
- `delete[] 指针`：释放 `new[]` 申请的数组内存
- `nullptr`：空指针。内存释放之后，指针还存着旧地址（危险的野指针），赋值为 nullptr 代表这个指针现在不指向任何有效内存

> 配对硬性规则：怎么申请，就怎么释放 `new` ↔ `delete` `new[]` ↔ `delete[]` 不能交叉混用

### 重点踩坑：指针自增遍历数组

- `arr + i` / `*(arr + i)` / `arr[i]`：只是临时算出一个新地址，**不会修改 arr 本身存的地址**，原始首地址保留，后续`delete[]`安全 ✅
- `arr++`：等价于 `arr = arr + 1`，直接修改指针变量 arr 里面存的地址，遍历完之后 arr 不再指向数组开头 ❌
- 致命规则：**`delete[]` 必须传入当初 `new[]` 返回的原始首地址**，地址偏移之后释放，程序直接崩溃，报错：`munmap_chunk(): invalid pointer`、core dumped
- 安全遍历方案：拷贝一份临时指针去自增遍历，保护原始首地址

```
int* tmp = arr;
for(int i=0;i<4;i++){
    std::cout << *(tmp++) << std::endl;
}
// arr从头到尾不变，正常delete[] arr
```

### 易混区分：原生数组名 vs 指针变量

```
int a[4];   // 栈上原生数组，a是地址常量，a++ 编译报错，不能修改
int* arr = new int[4]; // 指针变量，arr++ 语法合法，但是会弄丢首地址
```

> 如果 `new int[4]` 之后，只用 `delete arr`（不带方括号），会出什么问题？ （后面学到更深内容再补答案，先标记）
>
> 补充踩坑：`new[]` 后使用 `delete arr`（不带 []） 现象：编译不报错、有时候运行看起来正常 本质：属于 C++ 标准里的未定义行为，只是侥幸没有触发崩溃，代码依然是错误的，绝对不能这么写。 简单类型（int）容易蒙混过关；复杂类型一定会出问题。

## M0 Week1 Day3
### 主题：const 与 const 指针
核心口诀：**const靠近谁，就锁谁**

名词约定
- 指针本身：指针变量里面存的内存地址
- 指向的数据：`*p`，对应地址上存储的内容

1. `const int a = 10;`
普通编译期常量对象，定义时必须初始化；编译器可能把它放到只读段rodata，内存本身硬件层面禁止写入。

2. `const int* p`
const 在`*`左侧 → 锁住**指针指向的数据**
✅ p本身可以修改指向，可以`p++`、`p=&other`
❌ 不允许 `*p = xxx`
> 用途：只读buffer、只读数组入参，AI Infra算子函数最常用

3. `int* const p`
const 在`*`右侧 → 锁住**指针本身存的地址**
✅ `*p = xxx` 合法，可以修改指向的数据
❌ p不能重新赋值、不能p++、不能换指向

4. `const int* const p`
双重const，指针地址、指向的数据全部锁定，两者都不能修改。

---
### 关键区分：常量对象 vs 仅带const访问限制的指针
- 真正的常量对象：`const int a = 10;`
对象本身就是常量，内存有可能放在只读段。尝试修改它属于未定义行为。
- 可读写内存 + const指针（本次T3例子）
```cpp
const int* arr = new int[]{1,3,5,7};
```

堆内存本身是可读写的；`const int*`仅仅是**这个指针的访问权限被约定为只读**，不是内存焊死不能写。
换一个不带 const 的普通指针，依然可以修改这块内存（不推荐工程上这么干）。

> 
> 类比：东西本身能写，你手里这把钥匙是只读钥匙，不代表东西本身不可修改。

---

### new [] 数组初始化规则（C++11 及以后）

`new`分两种语法，**有没有`[]`是分水岭**

1. `new int{10}`：没有`[]` → 分配**单个 int 对象**，值初始化为 10；释放用`delete p;`
2. `new int[]{1,3,5,7}`：带`[]` → 分配 int 数组，列表初始化；释放必须配对`delete[] p;`

其他初始化写法

- `new int[4]()`：4 个 int，全部值初始化为 0
- `new int[4]{1,2}`：部分初始化，剩余元素自动补 0
- `new int[4]`：无初始化，内存里是随机脏值

⚠️ 硬性规则：`new[]` 必须搭配 `delete[]`；`new`（单个对象）搭配`delete`，不能混用。

---

### 栈数组 vs 堆数组（实操维度，抛开栈先进后出）

栈数组：`int arr[] = {1,3,5,7}`
堆数组：`int* arr = new int[]{1,3,5,7}`

1. 内存上限
栈空间很小（通常几 MB），不适合开很大的数组，开大直接栈溢出崩溃；
堆受整机内存限制，可以分配很大的 buffer，AI Infra 里张量、大输入输出 buffer 都放堆。
2. 生命周期
栈数组：绑定作用域 / 函数，出花括号、函数返回之后内存自动回收，地址失效，返回栈数组地址会得到野指针。
堆数组：只要不调用`delete[]`，内存一直存活；可以把指针 return 出去，跨函数传递使用。
3. 长度灵活性
栈数组一般要求编译期确定长度；
堆数组支持运行时动态指定长度，适合 shape 运行时才确定的张量场景。
4. 性能
栈分配开销极低，速度快；堆分配需要向操作系统申请内存，有少量开销。

选型准则

- 栈数组：小数组、固定长度、仅当前函数内部临时使用
- 堆数组：大块 buffer、运行时确定长度、跨函数传递、需要长期持有

---

### const_cast 补充（仅了解，尽量少用）

`const_cast` 专门用来增加 / 移除 const 修饰，**不改变底层数据类型**。
风险：

- 如果原始内存是堆内存：内存本身可读写，去掉 const 修改语法合法，但破坏只读语义，不推荐。
- 如果原始是编译期常量对象：修改属于未定义行为，程序可能崩溃、结果异常。

## M0 Week1 Day4

### 主题：引用 &，三种函数传参方式
引用（reference）：给一个**已经存在的变量起别名**，引用本身不分配独立内存。
引用硬性规则：
1. 定义的时候必须初始化，不能先声明再赋值；
2. 一旦绑定某个变量，**终身不能更换绑定目标**；
3. 对引用赋值，等价于对原始变量赋值，不是重新绑定。

> 易错坑：
> ```cpp
> int a = 100;
> int &ref = a;
> int b = 999;
> ref = b; // 不是ref绑定到b！等价于 a = b，只是拷贝数值
> ```

### 三种传参方式对比
1. 值传递 `void func(int a)`
进入函数时拷贝一份新数据；函数内部修改a，完全不影响外部实参。
开销：复制数据。适合很小的基础类型。

2. 指针传递 `void func(int *p)`
传递变量的地址；通过`*p`修改外部内存；需要手动取地址、解引用。
优点：可以传数组、可以传空指针；缺点：写法繁琐，需要警惕空指针。

3. 普通引用传递 `void func(int &a)`
a就是外部实参的别名；函数内修改a，外部变量同步变化；不用写`*`，代码简洁。
限制：不能接收字面量、临时值。

4. const引用 `void func(const int &a)`
只读别名，函数内不能修改；**可以接收字面量、临时对象**，还避免拷贝。
> AI Infra高频用途：传递大buffer、张量、大结构体，不想拷贝，也不允许修改。

### 本次T3两种合法实现对比
版本1（你本次实现，指针版，算子buffer常用）
```cpp
void add(const int* a,const int* b,int &res){
    res = *a + *b;
}
```

`const int*`：限制不能通过该指针修改 buffer；指针本身可以移动（a++ 合法）。

版本 2（题目原型，const 引用版）

```
void add(const int &a, const int &b, int &res){
    res = a + b;
}
```

`const int &`：单个变量只读别名，适合传单个数值。

### swap 练习踩坑记录

加减法 swap：简单好用，但如果两个地址是同一个变量，结果会变成 0；工程稳妥写法优先用临时变量 tmp 交换。

```
void swap_ref(int &a,int &b)
{
    int tmp = a;
    a = b;
    b = tmp;
}
```

运行结果规律：

- 值传递 swap：无法修改外部变量，交换失效
- 指针 swap / 引用 swap：都可以修改外部变量，交换成功

### 面试思考题

1. `int &r = 10;` 编译失败；普通引用不能绑定字面量临时对象。
2. `const int &r = 10;` 编译通过；const 引用可以延长临时对象的生命周期。

### 引用 vs 指针核心区别

- 指针：是独立变量，存地址，可以随时改变指向，可以为 nullptr
- 引用：只是别名，无独立内存，绑定后不可更换目标，不能为空

## M0 Week1 Day5
### 主题：std::vector 动态容器，张量buffer封装
vector 本质：**封装在C++里的堆数组**，底层数据在堆上连续存放，自动管理 new[] / delete[]，出作用域自动析构释放内存，无需手动释放。
头文件：`#include <vector>`

### 基础初始化方式
```cpp
vector<int> vec;            // 空vector，size=0
vector<int> vec(4);         // 4个int，默认初始化为0
vector<int> vec{1,3,5,7};   // 列表初始化，4个元素
```

常用接口

- `.size()`：当前有效元素个数
- `.capacity()`：当前预分配的堆空间容量（≥size）
- `.data()`：返回底层 buffer 裸指针 `T*`，AI Infra 高频，用来传给 C 风格算子函数
- `.push_back(x)`：尾部追加元素，容量不足时自动扩容
- `.reserve(n)`：预分配空间，提前预留 n 个元素位置，减少扩容

> 
> 重点：`.data()`拿到的裸指针，**没有边界检查**，和原生数组指针风险一致。

---

### 遍历的致命坑（高频踩坑，本次重点）

1. C 字符串 `char*`：语言约定末尾自带 `\0`（数值 0）哨兵，可以用 `while(*p)` 遍历。
2. int /float 数组、vector 张量 buffer：**没有自动追加结束哨兵**！
❌ 两种错误写法，都会越界：

```
// 错误1：判断元素值是否为0
int *ptr = vec.data();
while(*ptr != 0) { ptr++; }
// 风险：数组内存在0会提前截断；后面内存非0则无限越界
```

```
// 错误2：判断指针本身是否等于nullptr
int *ptr = vec.data();
while(ptr != nullptr) { ptr++; }
// 风险：指针向后偏移，永远不会自动变成nullptr，无限越界访问
```

✅ 铁律：所有数字张量 buffer，**必须携带元素长度 n，for 循环 i < n**

```
int *ptr = vec.data();
int n = vec.size();
for(int i = 0; i < n; i++)
{
    cout << *ptr << endl;
    ptr++;
}
```

### 扩容与指针失效（面试高频）

保存 `auto p = vec.data()` 之后调用 `push_back`：

- 如果 `vec.capacity() > vec.size()`：空间充足，**不扩容，指针仍然有效**
- 如果 `vec.capacity() == vec.size()`：触发扩容，申请新堆、拷贝数据、释放旧内存
→ 原来保存的 p 指向已经释放的内存，**野指针，失效**

> 
> 工程准则：push_back 之后，不要再复用之前缓存的 data 指针，重新调用 `.data()`。
> 预分配优化：`vec.reserve(1024)`，适合提前知道张量最大长度的算子场景。

### vector 传参方案（AI Infra 标准）

1. `void func(vector<int> v)` —— 值传递
调用时**完整拷贝整个 vector**，堆内存重新分配、全部元素复制。
缺点：大张量时拷贝耗时、内存翻倍，极端情况 OOM。Infra 代码禁止这么传大 buffer。
2. `void func(vector<int>& v)` —— 普通引用传递
别名，零拷贝；函数内部可以修改原 vector 内容。适合原地算子（inplace）。
3. `void func(const vector<int>& v)` —— const 引用传递
别名，零拷贝；函数内部禁止修改，只读。适合算子输入张量。

> 
> 本次 T3 的 square_inplace 就是标准 inplace 引用写法。

### 与裸指针算子打通（T2 练习）

算子接口习惯：`void print_buffer(const int* buf, int n)`

- `const int*`：只读 buffer，函数内不能修改 buffer 数据
- n：有效元素数量，用来控制遍历边界
调用方式：`print_buffer(vec.data(), vec.size());`
真实 CUDA/CPU 算子都是这种风格：裸指针 + 长度。

### 安全访问补充

- `vec[i]`：下标访问，**不做边界检查**，越界静默踩内存
- `vec.at(i)`：带边界检查，越界直接抛异常，调试阶段优先用 at

### 绝对禁止

```
int* p = vec.data();
delete[] p;  // ❌ double free！vector析构时会自动释放这块堆内存
```

2. T2：算子传入的 n 必须和真实有效长度匹配，不要随便写死数字

### 思考题复盘

Q1：`void func(vector<int> v)` 传大 vector 会发生什么？
A：值传递，完整拷贝全部元素，占用双倍内存，拷贝开销巨大，大张量容易性能暴跌、内存耗尽。Infra 用 const 引用 / 普通引用规避拷贝。

Q2：`vec.data()`拿到裸指针之后，如果执行`vec.push_back()`，指针还有效吗？
A：不一定。容量充足不扩容则有效；容量满触发扩容，旧指针失效，变成野指针。

# Day5 笔记：unique_ptr & RAII（AI Infra 张量底层基础）

> 前置：Day4 手写裸指针版 MyVector，痛点：手动 new/delete、浅拷贝 → double free、容易内存泄漏 编译标准：`-std=c++17`（make_unique 要求 C++14+，AI Infra 工程统一 C++17）

## 术语对照

- RAII：Resource Acquisition Is Initialization，资源获取即初始化
- unique_ptr：独占式智能指针（exclusive smart pointer）
- ownership：内存所有权

## 核心知识点

1. RAII 思想 资源生命周期绑定栈对象生命周期：

- 构造阶段：申请资源（堆内存、GPU 显存、文件句柄）
- 析构阶段：自动释放资源 对象离开作用域 `{}`，析构自动执行，**不用手动释放，异常 / 提前 return 也不会漏释放**。

1. unique_ptr<T[]>

- 独占语义：同一块堆内存，**同一时间只能有一个 unique_ptr 持有所有权**
- 拷贝构造、拷贝赋值被 `delete`，**禁止拷贝**，编译期拦截浅拷贝
- 支持 `std::move`：所有权转移，不复制内存；转移后源 unique_ptr 置空
- 数组版本 `unique_ptr<T[]>` 支持下标 `[]`，**不支持指针算术（`data + idx`）**
- 出作用域自动析构，自动调用 `delete[]`

1. 关键接口

- `make_unique<T[]>(N)`：安全分配 N 个元素的数组，推荐写法
- `.get()`：取出底层裸指针，**只拿指针，不转移所有权**
- `.reset()`：释放当前托管内存，可接管新内存
- `std::move()`：触发移动赋值 / 移动构造，转移所有权

1. UniqueVector 改造要点（对比 Day4 裸指针版本）

- 私有成员：`unique_ptr<T[]> data_;` 替代裸指针 `T* data_`
- 不需要手写析构函数，data_自动释放 buffer
- 扩容逻辑：新 buffer 用 make_unique 分配，`data_ = std::move(new_data_)` 转移所有权
- 对外接口不变：`size()` / `capacity()` / `operator[]` / `push_back`，上层调用无感知

## 思考题答案

1. 不需要手动写析构函数。`unique_ptr<T[]>` 是 RAII 封装对象，当 UniqueVector 对象生命周期结束时，成员`data_`会自动调用自身析构，自动执行`delete[]`释放数组内存。
2. unique_ptr 的拷贝构造、拷贝赋值运算符被标准库显式删除，目的是实现独占所有权，防止浅拷贝造成 double free。`std::move` 不会拷贝内存，触发移动赋值：把底层裸指针所有权从源 unique_ptr 转移给目标；转移完成后，源 unique_ptr 被置空，不再负责这块内存的释放。
3. 使用 `.get()` 的场景： CUDA、C 风格底层 API、算子库只接收裸指针，不支持 C++ 智能指针类型，这时用`.get()`取出裸指针传给底层接口。 风险：`.get()` 仅获取指针，**所有权仍然留在原 unique_ptr**；一旦 unique_ptr 销毁 /reset，内存被释放，拿到的裸指针变为野指针，后续访问属于未定义行为（崩溃、脏数据）。

## 踩坑清单

1. `make_unique` 需要 C++14+，编译命令务必加 `-std=c++17`
2. `unique_ptr<T[]>` 不能写 `data_ + idx`，只可以 `data_[idx]`
3. 禁止把 `.get()` 拿到的裸指针交给另一个 unique_ptr，会造成 double free
4. 扩容之后记得更新 `capacity_`，否则 size 判断逻辑错乱
